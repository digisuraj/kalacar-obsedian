## Scope locked for v1

- A Next.js + TypeScript storefront/API and a separate React + TypeScript owner dashboard, both developed locally first.
- Use the owner-created temporary MySQL database assigned to `kalacar.in`; do not access or modify any other database. Its app connection must use a specific remote IP allowlist, never “Any Host.”
- Dashboard access uses Google sign-in through the Next.js API plus a server-side owner allowlist (`KALACAR_OWNER_EMAILS`). The earlier mock owner sign-in was removed on 2026-11-04. Login is enabled on the hosted test addresses since 2026-11-05.
- Git repositories were created only after the owner asked. Keep storefront and dashboard changes in their separate repositories; use the dated feature branches and commit/push only after the owner verifies the feature.
- Customer storefront plus a visually separate owner dashboard in a React + TypeScript app; both use the Next.js server API and the same database. The dashboard does not need SEO or a second database connection from the browser.
- Shop small 3D-printed Hindu deity idols/devotional decor. Respectful, calm product presentation; no apparel or generic marketplace styling.
- Both interfaces work on mobile and desktop. **Mobile-first** layout, then desktop refinement.
- The storefront supports **light and dark themes**. The initial lightweight dashboard is **light theme only**; defer dashboard dark theme and advanced styling until the owner requests a later dashboard refinement.
- The owner can create products in the dashboard with one to five images; images are stored locally for development and joined to the product record in the Kalacar database.
- Customer access: email/password and Google sign-in.
- Keep promotions truthful: show a discount only when the owner supplies a real regular price and sale price; do not use invented compare-at prices, countdowns, or scarcity claims.
- Never create demo business data or show hardcoded business fixtures. Use owner-entered products and database-backed orders only; show truthful empty/unavailable states. The former local demo-login exception is retired: real Google credentials exist, and the demo accounts were deleted on 2026-11-04. Test-mode payment remains separate from business data and must never charge real money.
- The owner approved building the storefront and lightweight dashboard in parallel so product and stock workflows can be reviewed together. Both interfaces must use the same database through the server API.
- Inventory and orders must share one server-side source of truth. Stock checks and stock decrement/order creation must be atomic; concurrent requests for the final unit must not oversell. Dashboard inventory edits must use the same API and database as storefront checkout.
- Cart, address/pincode, Razorpay, customer order history, and a full-featured WooCommerce-parity owner dashboard (Shell, Overview, Orders, Products, Customers, Coupons, Settings) detailed in [[18-woocommerce-parity-and-dashboard-spec]].
- Ruthlessly de-bloated: dropped LiteSpeed cache, Hostinger AI generator, Printful ads, and third-party extension marketplaces.
- Owner packs and ships manually through Trackon and India Post. Tracking is planned below (Stage 5.2A); no automatic courier booking.
- Local development and test payment mode first. Hosting/domain/live payment are later release steps.

**Research 2026-11-05 (recheck when building)**
- **WhatsApp:** official click-to-chat link is `https://wa.me/<number>?text=<URL-encoded message>`. The number is in full international format with digits only, e.g. `919XXXXXXXXX`. The text is prefilled in the message box. WhatsApp's page doesn't state it, but we expect the owner must press Send. Source: https://faq.whatsapp.com/5913398998672934

- **Call:** `tel:<number>` has no message. On a computer it depends on a linked phone or calling app.
